# 시에스타 이벤트 기준

> 최종 갱신일: 2026-07-20
> 목적: 시에스타 만담의 제품 역할, 현재 구현 상태, 미구현 범위와 재활성화 조건을 한곳에서 관리한다.

## 1. 현재 판정

시에스타 이벤트 데이터는 삭제되거나 주석 처리되지 않았다. 텍스트 만담 엔진과 컨트롤러 연결은 보존되어 있지만, `bar_tend/src/hooks/restation-controller-model.ts`의 `SIESTA_EVENTS_ENABLED = false` 때문에 실제 플레이에서는 발생하지 않는다.

- 최초 비활성화: `a64f0d9` — 카루아 단독 핵심 흐름을 안정화하기 위한 임시 제외
- 구조 이동: `c522f0b` — P3 리팩터링에서 플래그 위치만 이동했으며 `false` 유지
- 현재 런타임 발생 횟수: 0회
- `siesta-setting`/`siesta-mention`: 사용자가 시에스타를 물을 때 카루아가 설명하는 별도 대화 경로이며 정상 동작
- 시에스타 캐릭터 프로필과 화면 스프라이트: 아직 런타임에 등록되지 않음

과거 `WORK_LOG.md`와 `TASK_BOARD.md`의 “이미 런타임에 활성화” 문장은 당시 검수 오류다. 현재 상태는 코드 플래그를 기준으로 판단한다.

## 2. 제품 역할과 장면 문법

시에스타는 상시 대화 상대나 추천 담당자가 아니다. 카루아가 주도하는 대화를 방해하지 않는 낮은 빈도의 생활형 만담 이벤트 캐릭터다.

```text
IDLE
  -> INTERRUPTING  시에스타가 직전 맥락에 예고 없이 난입
  -> BANTER        카루아 또는 손님과 짧게 만담
  -> EXITING       재고·청소·잔 정리 같은 업무 복귀 발화
  -> RETURN        카루아가 손님에게 대화권 반환
  -> COOLDOWN
  -> IDLE
```

장면 원칙:

- 시에스타는 인사하거나 손님을 맞으러 등장하지 않는다.
- 첫 발화는 직전 사용자 발언, 카루아 응답 또는 추천 결과와 연결한다.
- 시에스타는 관찰·보충·짧은 주의를 말하며 카루아의 농담을 해설하거나 교정하지 않는다.
- 카루아는 시에스타를 과하게 존경하거나 말의 깊은 뜻을 대신 설명하지 않는다.
- 두 캐릭터가 손님을 배제한 채 긴 대화를 이어가지 않는다.
- 시에스타의 마지막 발화는 한 문장 이내의 업무 복귀다.
- 최종 발화는 카루아가 손님에게 대화권을 돌려준다.
- 추천 질문, 안전 확인, 퇴장, 초기화, 추천 취소 흐름에서는 시작하지 않는다.

캐릭터 말투와 금지 패턴의 원문 계약은 `CHARACTER_DESIGN.md`, 상태 흐름과 계층 경계는 `ARCHITECTURE.md`가 소유한다. 이 문서는 그 계약의 구현 상태와 활성화 판단을 소유한다.

## 3. 현재 구현된 텍스트 이벤트

### 이벤트 엔진

`bar_tend/src/lib/banter/siesta-event.ts`에 다음 기능이 보존되어 있다.

- 7개 분기: `recommendation`, `strong`, `tired`, `celebration`, `sweet`, `sad`, `default`
- 총 21개 대화 세트
- 모든 세트는 `시에스타 -> 카루아 -> 시에스타 퇴장 -> 카루아 반환` 4발화
- 세션당 최대 2회
- 이벤트 후 6턴 쿨다운
- 최근 사용한 대화 키 회피
- 추천 질문 진행 중, `safety`, `exit`, `recommendation-cancel` 차단
- 일반 대화는 사용자 입력 3회 전까지 차단
- 추천 완료 직후에는 추천 칵테일 기반 분기 허용

### 컨트롤러와 표시

`useRestationController.ts`는 사용자 입력 수, 이벤트 수, 쿨다운과 최근 대화 키를 세션 ref로 관리한다. 이벤트 결과는 카루아의 본 응답 뒤 `afterMessages`로 전달된다.

`useRestationPresentation.ts`는 카루아 응답의 타이핑 완료 후 4개 메시지를 순서대로 예약하고, 마지막 메시지 뒤 입력 가능 상태로 돌아간다. `DialogueBox.tsx`는 메시지의 `speaker`를 읽어 `카루아`와 `시에스타` 텍스트 라벨을 구분한다.

따라서 현재 플래그만 켜면 채팅창의 텍스트 만담은 동작하지만, 시에스타 전용 이미지나 등장·퇴장 연출은 나타나지 않는다.

## 4. 기획 대비 미구현 또는 불완전한 부분

| 영역 | 현재 구현 | 목표 또는 필요한 보강 |
|---|---|---|
| 이벤트 상태 | ref와 예약 메시지로 간접 관리 | `INTERRUPTING/BANTER/EXITING/RETURN/COOLDOWN`을 관찰 가능한 구조 상태 또는 cue로 표현 |
| 발생 빈도 | 조건 충족 시 반드시 발생 | “낮은 빈도”에 맞는 결정 규칙 또는 확률과 결정적 테스트 도입 |
| 맥락 연결 | 입력 키워드와 추천 칵테일로 분기 | 전달 중인 `replyText`를 실제로 활용하거나 맥락 적합성을 별도 규칙으로 검증 |
| 사용자 개입 | 4발화를 자동 예약하여 중간 응답 불가 | 시에스타에게 답하는 입력을 남은 길이 안에서 한 번 처리하는 정책 구현 또는 해당 기획 폐기 결정 |
| 시에스타 프로필 | 미등록 | 시에스타 대사를 자동 감사할 프로필과 금지 표현 계약 등록 |
| 화면 표시 | 화자 텍스트 라벨만 존재 | SPR-004 스프라이트, 모바일 겹침 방지, 이벤트 외 비표시 |
| 이벤트 동기화 | 텍스트 메시지만 반환 | SPR-005의 구조화된 `spriteCue`/`stageDirection`, 활성 화자·표정·퇴장 타이밍 |
| 통합 회귀 | 엔진·라벨 단위 테스트 존재 | 실제 컨트롤러 플레이에서 발생·차단·쿨다운·대화권 반환·초기화를 한 번에 검증 |

현재 “낮은 빈도”는 확률로 구현되지 않았다. 활성화하면 일반 대화 세 번째 사용자 입력에서 첫 이벤트가 발생하고, 이후 6턴 쿨다운이 끝난 다음 최대 한 번 더 발생할 수 있다.

## 5. 재활성화 게이트

`SIESTA_EVENTS_ENABLED`를 `true`로 바꾸기 전에 다음을 확정한다.

1. 텍스트 이벤트만 먼저 출시할지, SPR-004~005와 함께 출시할지 결정한다.
2. 세 번째 입력에서 반드시 발생하는 현재 빈도를 승인하거나 낮은 빈도 규칙으로 변경한다.
3. 이벤트 상태 또는 최소한 구조화된 cue 계약을 정해 카루아 프레젠테이션과 충돌하지 않게 한다.
4. 추천 질문·안전·퇴장·추천 취소·초기화에서 이벤트가 발생하지 않는 통합 테스트를 추가한다.
5. 일반 대화와 추천 완료 후의 4발화 순서, 6턴 쿨다운, 세션당 최대 2회, 마지막 카루아 대화권 반환을 실제 플레이 회귀로 검증한다.
6. 이벤트 중 사용자 입력을 큐에 넣을지, 차단할지, 시에스타 응답으로 처리할지 제품 계약을 확정한다.
7. 시에스타 대사와 카루아 만담 대사의 캐릭터 QA를 다시 실행한다.
8. `CURRENT_STATE.md`, `TASK_BOARD.md`, `HANDOVER.md`, README의 사용자 노출 설명을 실제 활성 상태와 동기화한다.

## 상태 요약

| 항목 | 현재 상태 |
|---|---|
| 목표 제품 | Re:Station 카루아 중심 대화형 칵테일 추천 MVP + 시에스타 만담 이벤트 |
| 현재 구현 | `bar_tend/` 경로에서 Re:Station 브랜드와 자연스러운 직원 응대를 적용한 추천 프로토타입 |
| 현재 단계 | RST-000 MVP 범위와 Phase 1~1.5 구조 작업 완료. 다음 구조 우선순위는 Phase 2 Response Pipeline이며, DLG-807~809 대사 수렴은 구조 안정화 순서와 함께 재검토한다. |

| 추천 원칙 | JSON·DB·규칙 기반으로 추천 결과 확정, 대사 소재는 입력 경로가 결정, WebLLM은 향후 말투 포장만 허용 |
| 수렴 원칙 | DLG-807~809 완료 전까지 WebLLM 확장, 새 추천 알고리즘, 새 캐릭터, 추가 이벤트 시스템 보류 |
| 현재 런타임 초점 | 시에스타 이벤트는 `SIESTA_EVENTS_ENABLED = false`로 비활성화하고, 카루아 단독 추천·제조·서빙 루프를 집중 점검 중 |
| 차기 세션 방향 | 자유입력은 열어 두되 진행은 웰컴드링크·추천·주문·XYZ·Farewell Phase·귀가로 닫는다. 기준 문서는 `SESSION_FLOW_SPEC.md` |
| 문서 진입점 | `mission_control/README.md`에서 필독 파일과 선택적 수정·검토 파일을 구분 |
| 빌드 | 통과: `npm.cmd run build` (`tsc --noEmit` 포함, 메인 JS 446.31 kB) |

| 자동 테스트 | Vitest 255개 전체 통과 |

## 향후 논의

- 1차 수렴 기간의 최상위 기준은 `CONVERGENCE_PRINCIPLES.md`다. DLG-807~809가 끝나기 전에는 WebLLM 확장, 새로운 추천 알고리즘, 새로운 캐릭터, 추가 이벤트 시스템을 시작하지 않는다.
- 차기 세션 구조의 최상위 기준은 `SESSION_FLOW_SPEC.md`다. 환상주점은 AI 챗봇이나 연애 미연시가 아니며, 호감도 엔딩·공략 루트·True/Bad/Happy End를 만들지 않는다.
- `DISC-001`: 대화 의미와 다음 행동을 JSON 계약으로 관리해 규칙 엔진과 향후 LLM이 동일한 경계를 사용하도록 한다.
- 칵테일 데이터 확장은 DEC-020에 따라 IBA 공식 레시피를 최우선으로 한다. IBA에 없는 변형·시그니처는 확인된 레시피를 기준으로 맛 설명만 보강하고, 정보 부족·검색 실패·출처 충돌 항목은 정식 DB가 아니라 관리자 검증 큐로 보낸다.
- 관리자 승인 전 항목은 정식 추천 후보로 사용하지 않는다. 이름만 있는 정보 부족 칵테일은 런타임에서 흥미롭게 반응하되 확인된 메뉴가 아니라고 안내한다.
- 공통 칵테일 DB는 최종형에서 필요할 수 있지만 유저 간 상호작용은 범위에 없다. MVP는 JSON을 유지하고, 이후에는 `official` DB와 관리자 검증 큐만 제공하는 BaaS 또는 얇은 백엔드를 우선 검토한다.
- JSON에는 대사 전문 대신 최소 의미·행동 계약만 저장한다. 검색 API는 사실 수집, 코드는 검증과 상태 전이, WebLLM은 짧은 말투 포장을 맡는다.
- 대사 풀은 칵테일 ID가 아니라 직접 주문, 감정·무드 주문, 취향 추론, 재료·베이스 언급, 랜덤 추천 같은 입력 경로 태그로 선택한다. FSM 상태는 말투·발화 리듬·애니메이션 클립을, 감정 상태는 표정 스프라이트와 세부 어조를 결정한다. 칵테일은 제조·서빙 대사의 변수로 결합한다.
- 스프라이트 작업은 WebLLM보다 우선한다. 먼저 카루아/시에스타 표정 슬롯과 파일명 계약을 고정하고, 이후 실제 PNG 에셋과 시에스타 난입 큐를 연결한다.

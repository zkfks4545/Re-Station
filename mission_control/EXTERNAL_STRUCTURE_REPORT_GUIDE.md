# 외부 구조 보고서 작성 가이드

> 최종 갱신일: 2026-06-23  
> 대상 문서: `mission_control/EXTERNAL_STRUCTURE_REPORT.md`  
> 목적: 외부 AI 또는 기획 협업자와 Re:Station 기획을 지속적으로 이어가기 위한 구조 보고서 작성·갱신 기준

## 문서의 역할

`EXTERNAL_STRUCTURE_REPORT.md`는 내부 작업 로그가 아니라 외부 전달용 브리핑 문서다. 외부 AI가 코드베이스 전체를 읽지 않아도 현재 제품 구조, 추천 시스템, 대사 계층, 캐릭터 경계, 남은 기획 쟁점을 이해하도록 만든다.

이 문서는 구현 지시서가 아니다. 외부 AI에게 바로 코드 수정을 맡기기 위한 문서가 아니라, 기획안·대사 구조·검수 기준을 받아오기 위한 공유 자료다.

## 작성 원칙

1. 현재 구현된 사실과 앞으로의 희망 사항을 분리한다.
2. 추천 엔진, 대사 계층, UI 연출, 캐릭터 설정을 섞어 쓰지 않는다.
3. 외부 AI가 오해하기 쉬운 금지선을 먼저 적는다.
4. 파일 경로는 실제 경로를 쓴다.
5. 검증 상태는 마지막으로 확인한 명령과 결과만 적는다.
6. 카루아 말투나 시에스타 역할은 요약하되, 최종 원문 기준은 내부 문서로 연결한다.
7. 외부 AI에게 코드 구현을 요청하지 말고 기획·샘플·검수 기준을 요청한다.

## 갱신해야 하는 경우

아래 중 하나라도 바뀌면 `EXTERNAL_STRUCTURE_REPORT.md`를 갱신한다.

- 추천 질문 정책이나 후보군 압축 방식이 바뀐 경우
- 대사 데이터 위치나 프리셋 구조가 바뀐 경우
- `persona.ts`, `dialogues.json`, `keyword-rules.json`, `text-presets.ts`의 역할이 바뀐 경우
- 카루아/시에스타 말투 기준이나 금지 패턴이 바뀐 경우
- 시에스타가 등장하는 방식이나 이벤트 구조가 바뀐 경우
- WebLLM, 검색 API, 관리자 검증 큐 같은 역할 경계가 바뀐 경우
- 외부 AI에게 넘길 과제 범위가 바뀐 경우
- 검증 상태나 테스트 수를 외부 공유에 사용할 필요가 있는 경우

## 갱신하지 않아도 되는 경우

아래 변경은 보통 `WORK_LOG.md`, `CURRENT_STATE.md`, `TASK_BOARD.md`에만 기록하고, 외부 보고서는 필요할 때만 요약 반영한다.

- 작은 CSS 조정
- 내부 함수명만 바뀐 리팩토링
- 테스트 파일만 추가된 경우
- 외부 기획자가 알 필요 없는 구현 세부 버그 수정
- 아직 승인되지 않은 아이디어 메모

## 권장 구조

외부 구조 보고서는 다음 순서를 유지한다.

1. 프로젝트 한줄 요약
2. 현재 제품 컨셉
3. 반드시 지켜야 하는 핵심 경계
4. 주요 파일 지도
5. 사용자 입력 처리 흐름
6. 현재 대사 구조
7. 카루아 말투 계약
8. 시에스타 구조
9. 추천 시스템 구조
10. 데이터 구조
11. 현재 구조적 문제
12. 외부 기획자에게 요청할 기획안 범위
13. 외부 AI에게 줄 수 있는 과제 예시
14. 추천 후속 작업 순서
15. 현재 검증 상태
16. 기획안 평가 기준

섹션을 추가할 수는 있지만, 외부 AI가 빠르게 읽어야 하므로 중복 설명보다 기존 섹션의 갱신을 우선한다.

## 외부 AI에게 전달할 때

외부 AI에게는 보통 아래 3개를 함께 전달한다.

1. `mission_control/EXTERNAL_STRUCTURE_REPORT.md`
2. `mission_control/CONVERGENCE_PRINCIPLES.md`
3. 현재 받고 싶은 기획 질문 또는 과제 문장

말투 검수가 핵심이면 `mission_control/CHARACTER_DESIGN.md` 또는 `bar_tend/src/lib/bartender/persona.ts`의 관련 부분을 추가로 전달한다.

구현 구조 검토가 핵심이면 `mission_control/ARCHITECTURE.md`를 추가로 전달한다.

## 외부 AI에게 요청하기 좋은 것

- 카루아 말투 금지 규칙 정리
- 대표 사용자 입력과 반응 방향
- `reaction / lead / recommend / explanation` 블록 샘플
- intent별 문단 구조
- 상태·요청별 대사 풀 설계
- 시에스타와 카루아의 말투 차이
- 대사 품질 검수 체크리스트

## 외부 AI에게 요청하지 않는 것

- 바로 코드 구현
- 추천 알고리즘 교체
- DB에 없는 칵테일 사실 생성
- 출처 없는 역사·유래·창작자 생성
- WebLLM이 추천 결과를 정하는 구조
- 카루아를 상담가처럼 만드는 위로 대사
- 시에스타를 상시 대화 캐릭터로 확장하는 설계

## 결과물을 가져온 뒤 처리

외부 AI가 만든 기획안은 바로 코드에 넣지 않는다. 먼저 아래 순서로 검수한다.

1. 추천 프로세스를 앞으로 미는가
2. 상담원식 대사가 아닌가
3. 술이 감정 문제의 해결책처럼 보이지 않는가
4. 현재 JSON/프리셋 구조에 옮길 수 있는가
5. 카루아와 시에스타의 역할을 섞지 않는가
6. 추천 엔진과 대사 표현 계층을 섞지 않는가

검수 후 반영할 내용은 `TASK_BOARD.md`의 해당 작업에 연결하고, 실제 반영 이력은 `WORK_LOG.md`에 남긴다.

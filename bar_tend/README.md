# Re:Station

카루아와 대화하며 취향에 맞는 칵테일을 추천받는 브라우저 기반 MVP입니다. 추천 결과는 DB와 규칙 엔진이 안정적으로 결정하고, 대화의 소재는 사용자가 그 결과에 도달한 입력 경로를 따라갑니다.

같은 칵테일이라도 직접 이름을 주문했는지, 쓴맛이나 도수 같은 취향으로 도달했는지, 특정 재료나 베이스를 언급했는지, 감정·무드에서 출발했는지에 따라 다른 대사 풀을 사용합니다. 칵테일은 제조와 서빙 대사의 변수로 결합하고, 추천 판단 자체는 대사 계층에서 바꾸지 않습니다.

## 실행

```bash
npm install
npm run dev
```

## 검증

```bash
npm run lint
npm run check
npm test
npm run build
```

`npm run build`는 TypeScript 검사를 먼저 실행한 뒤 프로덕션 번들을 생성합니다.

## 구조

- `src/lib/cocktails/database.ts`: 단일 `CocktailData` 컬렉션과 검색
- `src/lib/recommendation/question-engine.ts`: 규칙 기반 추천 질문, 후보 필터링과 선택
- `src/lib/dialogue/input-router.ts`: 안전, 퇴장, 이름 검색, 추천, 일반 대화의 입력 경로 결정
- `src/lib/bartender/`: 카루아 규칙 기반 대화
- `src/components/`: 바 화면, 추천 카드, 사이드바
- `src/lib/storage/`: 세션 취향과 도감 저장

## 대화 방향

- 주문 방식이 대사 풀을 결정하고, 칵테일은 제조·서빙 대사의 소재가 됩니다.
- 등록된 칵테일 이름 또는 별칭이 입력에 있으면 취향 기반 추천보다 우선합니다.
- 추천 질문은 맛과 풍미, 도수, 탄산, 베이스의 4축을 사용합니다.
- 반복감을 줄이기 위해 최근 사용 대사 제외, FSM 상태별 대사 풀 분리, 입력 경로 태그 필터링을 사용합니다.
- 대사량이 늘어나면 Ink 스크립트의 `shuffle`/`cycle`과 템플릿 변수 치환을 사용할 수 있습니다.

## 생성형 표현 계층

WebLLM 실행 경로는 제거했습니다. 대화와 추천은 내부 결정론적 엔진이 담당하며, 향후 외부 의미 보조가 필요해도 미등록 은유·복합 발화·암시적 취향의 구조화 후보만 제안할 수 있습니다. 상태, 추천 결과, 사실, 행동과 최종 표현은 내부 로직이 결정합니다.
